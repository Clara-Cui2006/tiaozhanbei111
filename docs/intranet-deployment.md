# 检察内网落地与权限标准

## 1. 部署拓扑

院内浏览器只访问 Nginx。Nginx提供前端静态资源并将 `/api` 反向代理到本机 FastAPI。FastAPI统一连接业务数据库和院内统一模型，浏览器不持有模型密钥，也不能直接访问模型。

第一阶段不直连办案系统2.0，不连接12345、公安、飞书、微信、高德或其他互联网服务。地图只加载 `public/maps` 中的本地文件。

## 2. 账号、数据范围与功能授权

权限分为数据可见范围与功能权限两条轴，后端对每次请求重新校验。

| 角色 | 默认数据范围 | 默认功能 |
|---|---|---|
| 普通用户 | 所属业务条线 | 汇总查看、所属条线案件查看、AI辅助 |
| 部门主任/主管 | 本部门全部案件 | 本部门案件查看、AI辅助、材料编辑 |
| 院领导 | 全院 | 全院汇总、全院案件和决策材料查看 |
| 数据管理员 | 全院案件元数据 | 导入、确认、回滚，不默认查看案件正文 |
| 系统管理员 | 无案件正文权限 | 用户、系统参数和完整审计管理 |

三级业务数据权限按“普通人员 → 部门负责人 → 院领导”执行：普通人员只看本人所属业务条线，部门主任/主管查看本部门全部数据，院领导查看全院业务数据、综合汇总分析和高层统计信息。

政治安全不随职级自动开放，必须单独授予：

- `political:read`：查看政治安全专项；
- `political:write`：编辑政治安全专项材料。

其他关键权限包括 `data:import`、`data:rollback`、`user:manage`、`system:manage`、`audit:read`、`ai:use`。管理员创建账号时按最小必要原则授权。

## 3. 审计标准

当前记录登录成功/失败、退出、案件详情查看及越权失败、用户创建、数据校验、确认入库、批次回滚、AI调用、检察建议新增修改和系统参数修改。记录用户、时间、终端IP、对象、结果和必要范围信息。

AI日志只保存输入 SHA-256 摘要、模块和关联案件编号，不在审计日志中复制案件全文。模型输出标记为待人工审核。

## 4. 数据导入口径

平台支持两类导入表：

1. 业务系统宽表：必填字段为案件编号、案件名称、业务条线、案件类别。
2. 政治安全特殊案件简表：以院方提供的特殊案件表头为准，字段为序号、案件名称、姓名、性别、特殊身份、涉案地点（非西城区标注具体哪个外区、外省）、是否西城户籍、移送时间、案由、简要案情(一句话）。

政治安全特殊案件简表不要求另填部门受案号、承办部门或案件类别。系统会根据案件名称、姓名、移送时间、案由和行号生成内部案件编号，默认业务条线为“政治安全专项”，案件类别为“政治安全特殊案件”，政治安全研判状态为“待人工复核”，政治安全风险等级为“关注”。这类数据只是进入专项研判池，不代表已经形成人工复核结论。

分类字段按两层填写：

- `法定罪名/案由`：内环分类，优先沿用《刑法》《民法典》等法定表达；
- `治理主题标签`：外环治理识别标签，可用英文逗号、中文逗号或顿号填写多个，例如“电信网络诈骗、涉老权益保护”。

街道归属只能使用：

- 已确认街道；
- 待确认地址；
- 跨街道案件；
- 与西城无地域关联。

只有已确认街道的数据进入十五街道统计。文件上传后先进入暂存批次，错误行不入库；数据管理员人工确认后写入正式业务库。批次回滚只删除该批次写入的数据，并保留审计记录。

线索闭环字段 `内部线索状态` 支持：未形成线索、系统研判、人工复核、研判确认、内部移送、办理反馈、纳入统计。平台展示内部流转状态，不直接推送外部单位。

政治安全字段采用四维人工研判口径：地点维度、行为内容、涉及主体、时间维度。`政治安全研判状态` 支持：不属于政治安全、待人工复核、人工研判、研判确认、纳入统计；未经过人工复核的数据不得作为政治安全结论。

政治安全特殊案件简表字段映射如下：

- 涉案地点（非西城区标注具体哪个外区、外省） → 地址、地点维度，并自动尝试识别西城十五街道；
- 案由 → 法定罪名/案由、行为内容；
- 特殊身份 → 涉及主体、重点专题、重点人群标签；
- 是否西城户籍 → 涉案主体是否常住/本地关联；
- 移送时间 → 受理日期；
- 简要案情(一句话） → 案件摘要。

政治安全模块只统计已被系统标记为政治安全类别的案件。高发风险类型可按案件数量排序；异常、高风险、高关注标签不能简单依据案件数量生成，应结合案件分类标签、风险规则匹配和人工复核结果。

当前导入器已实现字段校验、文件内案件编号去重、数据库唯一编号去重、治理主题多标签解析、街道归属状态校验和政治安全人工复核状态校验。共同犯罪归并、捕诉撤并和地址自动初判需要等待院方真实字段字典和脱敏样例后联调。

## 5. 院内模型配置

当前适配 OpenAI兼容的 `/chat/completions` 协议，配置项只存在服务器 `runtime.env`：

- `MODEL_BASE_URL`
- `MODEL_API_KEY`
- `MODEL_NAME`
- `MODEL_TIMEOUT_SECONDS`

未配置模型时，接口返回“院内统一模型尚未配置”，不会生成模拟答案。模型调用禁用系统代理，避免请求意外经由外网代理转发。正式联调前需由院方确认模型协议、认证方式、并发限制和可处理数据密级。

## 6. 服务器前置条件

院方运维预装 Python 3.11+、Nginx、systemd、rsync、curl 和 OpenSSL。离线交付包必须在与内网服务器相同 CPU 架构及兼容 Linux 环境构建，并核对 `SHA256SUMS`。

运行目录：

- 前端：`/var/www/community-legal-risk-platform`
- 后端：`/opt/community-legal-risk-platform/app`
- 数据库：`/var/lib/community-legal-risk-platform`
- 日志：`/var/log/community-legal-risk-platform`
- 配置：`/etc/community-legal-risk-platform/runtime.env`

服务只监听 `127.0.0.1:8090`，由 Nginx 对院内终端提供入口。数据库目录和配置文件不得进入 Web 根目录。

## 7. 尚待院方确认

- 服务器操作系统、CPU架构和数据库产品；
- 统一身份认证协议；
- 院内统一模型协议及认证；
- 正式案件字段字典、脱敏规则和样例；
- 各部门名称、人员角色与政治安全专项授权名单；
- 内网域名、证书、端口、防火墙、日志保存周期和备份制度。

SQLite仅用于当前底座和单机试运行。正式并发或国产数据库环境确定后，应将数据访问层迁移至院方指定的 PostgreSQL、人大金仓或达梦等数据库，并进行等保与密码应用要求下的专项配置。
