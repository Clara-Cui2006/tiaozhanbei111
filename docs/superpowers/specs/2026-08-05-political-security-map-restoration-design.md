# 政治安全地图恢复与蓝色视觉优化设计

## 背景与目标

政治安全页面最新版本将街道地图切换为 `echarts-gl` 三维渲染后，部分运行环境无法正常显示地图。同时，“西城重点专题与复核状态”中的“识别口径”与两项统计指标并列，信息层级不合理；“政治安全四维研判”和专题复核筛选区域的灰色观感也与页面蓝色体系不一致。

本次改动目标：恢复稳定、可交互的西城区街道地图；重新组织识别口径；统一政治安全研判区域的蓝色视觉语言。改动不改变后端接口、统计口径、权限边界或案件数据。

## 方案选择

采用标准 ECharts 二维地图系列，并通过浅蓝填充、边界描边、阴影和选中态营造轻立体效果。保留街道点击、缩放、复位、图例、筛选和详情联动。

不继续依赖 WebGL 三维地图作为主渲染路径，避免内网浏览器、旧显卡或 Electron 环境因 WebGL 支持差异出现白屏；不改用自定义 SVG，以免重复实现现有地图交互。

## 地图设计

- 使用仓库现有 `public/maps/xicheng_streets.geojson` 作为15个街道边界的首选来源，保留现有区级轮廓兜底逻辑。
- 使用标准 ECharts `map` 系列渲染，移除政治安全页面对 `echarts-gl` 的运行时依赖。
- 浅色主题采用接近参考图的淡蓝白背景、蓝色街道边界、柔和下投影和清晰街道标签。
- 案件数量仍通过蓝色深浅表达；选中街道使用亮青蓝描边和更明显的阴影。
- 深色主题保持现有深蓝基调，但提高边界、标签与选中态对比度。
- 保留放大、缩小、恢复全区、图例开合、街道点击、详情面板及筛选联动。
- 地图加载失败时继续显示明确错误和重新加载入口，不使用伪造边界或随机统计。

## “西城重点专题与复核状态”布局

- 第一层保留重点专题标签。
- 第二层并列展示“人工复核案件总量”和“重点专题案件总量”两项指标，维持数值与环形比例的对应关系。
- “识别口径”从指标网格中移出，在指标下方作为全宽、独立的信息说明区展示。
- 将原有重复的 `a-alert` 内容合并到该说明区，页面只保留一处口径解释。
- 说明区使用信息图标、短标题和分行正文，强调其为统计说明而非第三项指标。
- 窄屏下两项指标改为单列，说明区保持全宽。

## 四维研判与专题复核配色

- 四张研判卡统一使用蓝色渐变背景、蓝青色边框和轻微内高光，标题与正文保持清晰层级。
- “重点专题/复核状态”筛选区使用比卡片略深一级的蓝色背景和明确边框，避免与卡片混成灰色区域。
- 浅色主题使用淡蓝底和深蓝文字；深色主题使用深蓝底、浅蓝文字与青蓝强调色。
- 不引入红、橙等新的主色，避免与风险告警语义冲突。

## 数据流与兼容性

地图仍使用 `fetchXichengStreetMapOverview` 返回的街道案件数，并使用当前筛选器刷新。选中街道后仍调用现有详情接口；本次仅替换渲染配置和视觉样式，不改变接口参数或响应模型。

主题继续由现有主题检测和监听机制驱动。标准 ECharts 地图不要求 WebGL，兼容现有浏览器和 Electron 构建目标。

## 错误处理

- GeoJSON 首选文件读取失败时，继续尝试仓库内现有候选文件与内置区级轮廓。
- 数据接口失败时保持错误遮罩和“重新加载”按钮。
- 地图实例不存在或尚未完成初始化时，缩放和复位操作安全返回，不抛出页面级异常。

## 验证标准

- 政治安全页面首次进入时能够看到完整街道地图，不出现空白地图区域。
- 15个街道边界、名称、数量颜色和图例正确显示。
- 街道点击、放大、缩小、恢复全区、专题筛选、复核状态筛选和详情联动可用。
- 浅色主题视觉接近参考图的浅蓝立体效果；深色主题保持蓝色体系和足够对比度。
- “识别口径”独立全宽展示，不与两项案件总量并列，且不存在重复提示。
- 四维研判卡和专题复核筛选区不再呈灰色。
- `npm run type-check` 与 `npm run build` 通过。

## 非目标

- 不修改政治安全案件统计定义、专题种类或复核状态枚举。
- 不调整后端接口、数据库、权限或部署配置。
- 不制作新的行政区划数据，也不恢复任何公网地图依赖。
