# 西城区 Three.js 街道地图迁移设计

## 1. 目标

将 `E:\Create\zhihuixicheng` 中的西城区 15 街道 2.5D Three.js 地图迁入 `tiaozhanbei111` 首页的“街道案件数量分布”可视化区域。

迁移后满足以下目标：

- 3D 模式保留源项目的科技底座、立体街道、Bloom 发光、边界高光、中文标签和镜头效果。
- 保留自动旋转、拖动旋转、滚轮缩放、受限平移、悬浮抬升、点击选中、镜头聚焦和全区复位。
- 保留挑战杯项目当前的 2D 地图模式、顶部筛选条件、案件口径摘要、左下角图例、右侧街道详情及图表联动。
- 街道颜色由当前筛选结果中的实际 `caseCount` 决定，继续采用现有五档动态分级规则。
- 浅色和深色页面主题下，地图区域均保持源项目的深色科技视觉。

## 2. 范围

### 2.1 本次迁移包含

- 源项目清洗后的 15 街道 GeoJSON 及 ODbL 署名文件。
- Three.js 地图场景、街道几何、材质、标签、镜头、交互、选择状态、资源释放和科技底座实现。
- 源项目中与上述模块直接相关的测试用例。
- 挑战杯项目中 3D/2D 切换、地图控制按钮、街道选择和右侧详情加载的适配。
- `StreetMapOverview.streets` 到 Three.js 地图指标的转换层。

### 2.2 本次迁移不包含

- 替换挑战杯项目的页面顶栏、筛选栏、摘要卡片、右侧详情面板或底部说明。
- 改写现有 2D ECharts 地图。
- 修改案件统计接口的业务口径。
- 将源项目的独立首页、信息面板、工具栏和整体页面样式迁入挑战杯项目。

## 3. 方案选择

采用组件化迁移：3D 模式使用独立 Three.js 组件，2D 模式继续使用现有 ECharts 容器。

未采用 iframe 嵌入，因为它会引入双构建、跨页面状态通信和主题尺寸同步问题。未采用 ECharts 仿制，因为源项目的科技底座、Bloom、立体街道悬浮和镜头动画难以保持一致。

## 4. 架构

### 4.1 文件边界

计划新增以下独立单元：

- `src/components/xicheng-three-map/XichengThreeMap.vue`
  - Vue 生命周期入口。
  - 接收街道案件指标、当前选中街道和主题信息。
  - 向父组件发出悬浮、选择和错误事件。
  - 暴露放大、缩小、复位和聚焦方法。
- `src/components/xicheng-three-map/types.ts`
  - 定义地图 GeoJSON、案件指标、选择状态和组件公开方法。
- `src/components/xicheng-three-map/case-count-metrics.ts`
  - 将 `streetName`、`streetCode` 和 `caseCount` 转为 Three.js 地图使用的五档指标。
  - 统一街道名称、行政代码和最大值分档规则。
- `src/components/xicheng-three-map/map/`
  - 承载源项目的场景、几何、材质、标签、镜头、交互、选择状态、科技底座和资源释放模块。
- `public/maps/xicheng_15_streets_clean.geojson`
  - 使用源项目清洗后的 15 街道边界。
- `public/maps/ODbL_ATTRIBUTION.txt`
  - 保留地图数据来源与许可说明。

现有 `src/components/risk-map-panel.vue` 负责：

- 获取筛选结果与街道案件统计。
- 维护当前 3D/2D 模式和已选街道。
- 在 3D 模式渲染 `XichengThreeMap`，在 2D 模式渲染现有 ECharts 地图。
- 将页面控制按钮转发到当前地图实现。
- 接收 Three.js 街道点击事件并加载现有右侧详情。

### 4.2 依赖

- 在挑战杯项目增加与源项目兼容的 `three` 运行依赖。
- 增加对应的 `@types/three` 开发依赖。
- 不引入新的状态管理库或地图服务。

## 5. 数据流

1. `risk-map-panel.vue` 使用现有 `fetchXichengStreetMapOverview()` 获取 `StreetMapOverview`。
2. 适配层读取 `overview.streets` 中的 `streetName`、`streetCode` 和 `caseCount`。
3. 街道名称统一为带“街道”后缀的标准名称，行政代码优先用于匹配，名称作为兼容匹配键。
4. 计算当前筛选结果中的最大案件数 `maxCaseCount`。
5. 以最大案件数的 20% 为间隔划分五档，并生成与现有图例一致的冷蓝、青、金、橙、红颜色。
6. Three.js 街道材质和 2D ECharts 填色使用同一套分档函数。
7. 筛选条件变化后，重新获取 overview，更新材质、图例和已选街道统计。

零案件街道进入最低档，并显示案件数 0。全街道案件数均为 0 时，五档边界保持有效，避免除零和无效颜色。

## 6. 视觉与交互

### 6.1 3D 模式

- 保留源项目的透视镜头、雾效、灯光、ACES 色调映射、Bloom 和反光科技底座。
- 街道顶部颜色由案件数五档决定，侧壁使用对应渐变和边缘高光。
- 自动旋转在首次渲染后启用；用户拖动、滚轮或点击后暂停。
- 悬浮街道时整块轻微抬升并增强边界和标签。
- 点击街道后保持选中、镜头聚焦，并触发现有详情接口。
- 点击地图空白区域或复位按钮时恢复全区视角并清除选择。
- 页面“＋”“－”“⌂”按钮分别调用 Three.js 镜头放大、缩小和复位。
- 15 个中文标签继续使用源项目标签层；选中与悬浮状态提高显示优先级。

### 6.2 2D 模式

- 保留现有 ECharts 地图、呼吸覆盖层、标签布局、点击选择、缩放和复位。
- 从 3D 切换到 2D 时保留已选街道；从 2D 切换到 3D 时同步选中状态并聚焦该街道。
- 2D 和 3D 共用案件分档、图例与详情状态。

### 6.3 布局与主题

- 保持当前地图卡片尺寸、标题、模式切换、图例、控制按钮、说明文字和右侧详情面板布局。
- Three.js 画布只占据现有 `.xrm-map-box` 区域，不覆盖页面其他控件。
- 浅色页面主题仍展示深色 Three.js 场景，保证发光、反射和层次效果一致。
- 移动端继续使用现有响应式地图高度；地图镜头使用源项目的移动端视角系数。

## 7. 错误处理与资源管理

- GeoJSON 加载失败时，在地图区域显示明确错误信息，并保留 2D 模式切换入口。
- WebGL、后处理或 Three.js 场景初始化失败时，释放已创建资源并显示错误信息。
- 组件卸载或切换离开 3D 模式时，取消动画帧、断开尺寸监听、移除事件监听，并释放几何体、材质、纹理、渲染器和后处理资源。
- 数据中出现无法匹配的街道时记录警告；其余街道继续渲染。
- 接口加载失败沿用现有 overview/detail 错误提示，不伪造案件数。

## 8. 测试与验收

### 8.1 自动测试

- 案件数五档：最大值、20% 边界、零值、全零数据和筛选后重算。
- 街道映射：15 个标准名称、去除或补充“街道”后缀、行政代码优先匹配。
- 几何与投影：15 个街道均生成有效立体几何，边界数据不被修改。
- 选择状态：悬浮、选择、清除和 2D/3D 切换同步。
- 镜头控制：聚焦、放大、缩小和复位使用有效边界。
- 资源释放：卸载后停止动画与监听。

### 8.2 浏览器验收

- 3D 初始视图与源项目视觉一致，包含科技底座、发光边界、立体侧壁和标签。
- 自动旋转、拖动、滚轮、悬浮、点击、聚焦、放大、缩小和复位均可用。
- 点击任一街道后，右侧详情名称、案件总量和图表与该街道一致。
- 切换筛选条件后，街道颜色、图例区间和详情案件数同步更新。
- 3D 与 2D 切换保留当前选择，两个模式使用相同颜色档位。
- 浅色和深色主题下地图均保持源项目的深色科技效果。
- 桌面宽屏和移动端布局不溢出，不遮挡筛选器、图例和详情面板。
